# Runbook 8 — Findings acknowledgement, suppression, reopening

**Purpose:** work the directory findings queue (triage → acknowledge /
suppress → reopen).
**Prerequisites:** `directory:read` to view, `directory:write` to
transition (`admin` has both; read-only roles can only view).

Findings are generated by the insights scan — humans only change
lifecycle state. Every transition is audited.

## View

```bash
curl -sS "https://$HOST/api/v1/directory/findings?page=1&page_size=20" \
  -H "Authorization: Bearer $TOKEN"
curl -sS "https://$HOST/api/v1/directory/findings/summary" \
  -H "Authorization: Bearer $TOKEN"      # counts by status/category
```

Expected: `items[]` with `id`, `category`, `status` (`open` |
`acknowledged` | `suppressed`), timestamps; summary counts add up.

## Acknowledge

Use when the finding is real and being worked:

```bash
curl -sS -X POST https://$HOST/api/v1/directory/findings/$FID/ack \
  -H "Authorization: Bearer $TOKEN" -H "Origin: https://$HOST"
```

Expected: `200`, finding `status: "acknowledged"`. It stays visible in
the summary — acknowledged ≠ resolved.

## Suppress

Use when the finding is a known false positive (e.g. a service account
intentionally without inventory):

```bash
curl -sS -X POST https://$HOST/api/v1/directory/findings/$FID/suppress \
  -H "Authorization: Bearer $TOKEN" -H "Origin: https://$HOST"
```

Expected: `status: "suppressed"`. Suppressed findings leave the active
queue but remain queryable and audited.

## Reopen

```bash
curl -sS -X POST https://$HOST/api/v1/directory/findings/$FID/reopen \
  -H "Authorization: Bearer $TOKEN" -H "Origin: https://$HOST"
```

Expected: `status: "open"` — works from either acknowledged or
suppressed.

## State machine

```
open ──ack──► acknowledged ──reopen──► open
  │                                      ▲
  └──suppress──► suppressed ──reopen─────┘
```

`404` = wrong `finding_id` or cross-connection id; `403` = missing
`directory:write`; `409` never occurs (transitions are idempotent-
safe re-entries).

## Auto-regeneration caveat

The insights tick (`eitop.directory_insights_tick`, default every
600 s) regenerates findings from current state:

- A **suppressed** finding whose underlying condition persists stays
  suppressed (state is preserved across scans).
- If the condition disappears and later returns, treat the regenerated
  row as fresh — review suppression lists periodically
  (`GET /findings?status=suppressed`).

**Security warning:** suppression hides real gaps too — review
suppressed findings during audits ([runbook 16](log-inspection-audit-review.md)).
